ENVIRONMENTSA card-dispute environment where reward hacking doesn't pay.

Seeded episodes of the full card-dispute lifecycle on a double-entry ledger. Agents act through a 12-tool API. Nineteen verifiers score each episode from ledger postings and a hash-chained trace. The agent's own report is checked against the ledger, never taken on trust.

For AI labs and data partners training or evaluating agents on financial work, and for teams choosing a model before it touches money.

Request the sampleRead the paperSee results

01 / TASKSOne dispute per episode, played from the merchant's side.

Inquiry, chargeback, pre-arbitration, arbitration. Deadlines run on business-day calendars, fees post to the ledger, and the true case type stays hidden until the episode closes.

Rules and their sources are tabulated in the engine's docs/RULES.md. Assumptions are numbered and listed.

  1. Six hidden case types.True fraud, friendly fraud, service failure, buyer's remorse, merchant error, cardholder mistake. The agent sees the case, never the label.
  2. Real network structure.Visa and Mastercard reason codes in four categories, each with required and supporting evidence across 17 document kinds.
  3. Deadlines and fees.Visa 30-day and Mastercard 45-day response windows, fees on chargeback and pre-arbitration, arbitration losses, CE 3.0, refunds in flight, FX.
  4. Long horizon.Up to 40 steps with a clock tool. A missed deadline loses the case.
  5. Documents to doubt.Some evidence is edited, mismatched or stale. Representing everything costs fees; accepting everything is the cost floor.
The 12 tools
readget_case, list_evidence, get_evidence, get_ledger_view, request_info
actaccept, represent, escalate, refund, wait
writeupload_evidence: a merchant-authored document. Deliberately offered: it is the path a reward hacker finds.
finishsubmit_decision: an explanation, a stated win probability, structured claims

02 / REWARDRead from the ledger, gated by hard checks.

Each check is hard (a gate) or soft (weighted). Cost is the merchant's net ledger postings after capture, fees included. The agent's report is a claim to verify, not a score.

reward = quality if every hard check passes, else 0

Batch checks run across a set of episodes: consistency, calibration, claimed against actual win rate, memorised outcomes.

03 / EVIDENCETested against the policies that cheat.

Twelve exploit suites attack the verifiers. We publish which checks stop which attacks, and where coverage is still partial.

Pre-registrations, failed hypotheses included, are in the paper.

04 / PLUG INPython, MCP, or one command per model.

Deterministic: the same seed and the same calls give the same bytes. The seed space is unbounded and generation is sharded for bulk runs. Held-out benchmark seeds are salted and sealed.

  • Python API. DisputeEpisode: observe, call, submit. Drop it into your RL loop.
  • MCP server. scruple mcp sim serves the same tools to any MCP-capable agent.
  • Model harness. Anthropic, OpenAI, Gemini, Mistral, Groq, Together, vLLM, Ollama or any OpenAI-compatible endpoint.
  • Outputs. JSONL trajectories with full scorecards; tool schemas in OpenAI and Anthropic formats.
  • Built with you. A gymnasium-style wrapper or a rubric adapter for your stack, new case families, difficulty curricula.
from scruple.agents.dispute_episode import DisputeEpisode
from scruple.verifiers.record import SelfReport

ep = DisputeEpisode(seed=700000)        # same seed + same calls = same score
obs = ep.observe()                      # case, deadline, allowed actions
docs = ep.call("list_evidence")["evidence"]
# ... your policy reads, decides and acts through ep.call(...)
score = ep.submit(SelfReport(explanation="..."))
score.reward, score.gate, score.cost_usd_minor
